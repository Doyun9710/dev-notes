# 1.1 정보는 비트와 컨텍스트로 해석됨

> Information Is Bits + Context

## 핵심 개념

- 컴퓨터 시스템의 모든 정보는 결국 **비트(Bit)의 연속**으로 표현됨
  - 소스 코드
  - 문자열
  - 이미지
  - 실행 파일
  - 네트워크 패킷
  - 정수와 실수
- 비트는 `0` 또는 `1`의 값을 가지는 가장 작은 정보 단위
- 일반적인 현대 시스템에서는 **8비트 = 1바이트(Byte)** 로 묶어 처리
- 동일한 비트열도 어떤 방식으로 해석하느냐에 따라 의미가 달라짐

---

## 텍스트 파일도 비트로 저장됨

- `hello.c`와 같은 소스 코드도 컴퓨터 입장에서는 바이트들의 연속
- 문자는 문자 자체가 저장되는 것이 아니라 **문자 인코딩 규칙에 대응하는 정수 값**으로 저장됨
- CS:APP의 예제에서는 ASCII를 기준으로 설명

```text
h → 104
e → 101
l → 108
l → 108
o → 111
```

- 텍스트 파일도 내부적으로는 다음과 같은 형태로 표현됨

```text
문자
 ↓
정수 값
 ↓
바이트
 ↓
비트
```

---

## 비트와 컨텍스트

- 비트열 자체만으로는 데이터의 의미를 판단할 수 없음
- 동일한 비트 패턴도 컨텍스트에 따라 서로 다르게 해석 가능

예시:

```text
01000001
```

- 부호 없는 정수로 해석 → `65`
- ASCII 문자로 해석 → `'A'`
- 명령어나 다른 데이터의 일부로 해석 → 또 다른 의미

- 메모리에 저장된 비트열만 보고 다음 정보를 알 수는 없음
  - 정수인지
  - 실수인지
  - 문자인지
  - 문자열의 일부인지
  - CPU가 실행할 명령어인지
- 프로그램이 해당 비트를 어떤 규칙으로 읽고 처리하느냐에 따라 의미가 결정됨

> **비트 자체가 아니라, 비트를 해석하는 컨텍스트가 의미를 결정함**

---

## C 타입과 컨텍스트

- C에는 `int`, `char`, `float` 등의 타입이 존재
- 따라서 단순히 "데이터에는 타입이 없다"라고 표현하면 오해 가능
- 정확히는 **물리적으로 저장된 비트 패턴 자체에 의미가 항상 함께 저장되는 것은 아님**
- C 프로그램은 타입과 연산 규칙을 통해 비트를 어떻게 해석할지 결정

```c
int value = 65;
char ch = 'A';
```

- 두 값은 특정 상황에서 비슷한 비트 패턴을 가질 수 있지만 프로그램에서는 서로 다른 의미로 사용
- 타입은 데이터의 해석 방식을 결정하는 컨텍스트 중 하나

---

## 개발할 때 왜 중요한가

- 여러 시스템 문제는 **같은 비트를 어떻게 해석하느냐의 차이**와 연결됨
- 대표적인 사례
  - 문자 인코딩
  - signed / unsigned 정수 변환
  - 정수 overflow
  - floating-point 오차
  - binary protocol 파싱
  - 파일 포맷 해석
  - memory representation
- 이후 학습할 정수 표현, 부동소수점, 기계어, 메모리, 포인터 등의 기초가 되는 개념

---

## 정리

- 컴퓨터의 모든 정보는 비트로 표현됨
- 일반적으로 8비트를 1바이트로 묶어 처리
- 문자 역시 정수 값으로 인코딩되어 저장됨
- 동일한 비트 패턴도 해석 방식에 따라 다른 의미를 가질 수 있음
- 따라서 **정보를 이해하려면 비트와 이를 해석하는 컨텍스트를 함께 봐야 함**
