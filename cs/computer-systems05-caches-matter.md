# 1.5 캐시가 중요한 이유

> Caches Matter

## 핵심 개념

* 프로그램 실행 과정에서는 코드와 데이터가 여러 저장장치 사이를 계속 이동
* 이러한 데이터 이동에는 시간이 필요하며, 프로그램 성능에 직접적인 영향 발생
* 특히 CPU와 메인 메모리 사이에는 큰 속도 차이가 존재
* CPU가 필요한 데이터를 기다리는 시간을 줄이기 위해 **캐시 메모리(Cache Memory)** 사용

```text
CPU
 ↓
Cache
 ↓
Main Memory
```

* 캐시는 자주 사용할 가능성이 높은 데이터를 CPU 가까이에 보관
* 상대적으로 느린 메인 메모리 접근 횟수를 줄이는 것이 핵심 목적

---

## 프로그램 실행과 데이터 이동

* 프로그램 실행은 단순히 CPU가 명령어를 계산하는 과정만을 의미하지 않음
* 코드와 데이터가 저장장치 사이를 계속 이동하는 과정 포함

`hello` 프로그램 실행을 단순화하면 다음과 같은 흐름

```text
Disk
 ↓
Main Memory
 ↓
CPU
 ↓
I/O Device
```

* 실행 파일

  * 디스크에서 메인 메모리로 이동

* CPU가 실행할 명령어와 데이터

  * 메인 메모리에서 CPU로 이동

* 출력 결과

  * CPU와 I/O 시스템을 거쳐 디스플레이로 전달

* 이러한 데이터 이동은 프로그램의 실제 계산과 별개로 추가적인 비용 발생

* 따라서 시스템 성능을 높이려면 **필요한 데이터를 가능한 한 빠르게 CPU에 전달하는 구조** 필요

---

## CPU와 메인 메모리의 속도 차이

* CPU 연산 속도는 매우 빠름
* 반면 메인 메모리인 DRAM은 CPU보다 상대적으로 느림
* CPU가 필요한 데이터를 메모리에서 가져오는 동안 대기하는 상황 발생 가능

```text
CPU 연산
   ↓
데이터 필요
   ↓
Main Memory 접근
   ↓
데이터 대기
   ↓
CPU 실행 재개
```

* CPU가 아무리 빠르게 연산해도 필요한 데이터가 도착하지 않으면 다음 작업 진행 불가
* 결과적으로 메모리 접근 시간이 프로그램 성능의 병목으로 작용 가능

---

## 캐시 메모리

* CPU와 메인 메모리 사이의 속도 차이를 줄이기 위한 작고 빠른 저장 공간
* 일반적으로 메인 메모리의 DRAM보다 빠른 **SRAM(Static RAM)** 기반
* CPU 내부 또는 CPU와 매우 가까운 위치에 배치

```text
CPU
 ↕
Cache (SRAM)
 ↕
Main Memory (DRAM)
```

* SRAM

  * 빠른 접근
  * 높은 비용
  * 작은 용량

* DRAM

  * SRAM보다 느린 접근
  * 상대적으로 낮은 비용
  * 큰 용량

* 모든 메모리를 빠른 SRAM으로 구성하는 것은 비용과 용량 측면에서 비효율적

* 따라서 작은 SRAM을 캐시로 사용하고 큰 DRAM을 메인 메모리로 사용하는 구조 채택

---

## 캐시는 일부 데이터만 보관함

* 캐시는 메인 메모리의 모든 데이터를 저장하지 않음
* 자주 사용하거나 곧 다시 사용할 가능성이 높은 데이터 일부만 보관
* CPU가 필요한 데이터를 캐시에서 찾을 수 있다면 메인 메모리까지 접근할 필요 감소

```text
CPU
 ↓
Cache
 ↓
데이터 존재
 ↓
빠르게 사용
```

* 캐시에 데이터가 없다면 메인 메모리에서 데이터를 가져와야 함

```text
CPU
 ↓
Cache
 ↓
데이터 없음
 ↓
Main Memory
 ↓
Cache
 ↓
CPU
```

* 결과적으로 캐시는 느린 메모리에 직접 접근하는 횟수를 줄이는 역할 수행

---

## 지역성 — Locality

* 작은 캐시만으로도 높은 효과를 얻을 수 있는 중요한 이유
* 프로그램은 메모리 전체를 완전히 무작위로 접근하는 경우가 많지 않음
* 최근에 사용한 데이터 또는 그 주변 데이터를 다시 사용할 가능성이 높은 경향 존재
* 이러한 특성을 **지역성(Locality)** 이라고 함

### 시간적 지역성 — Temporal Locality

* 최근 사용한 데이터는 가까운 미래에 다시 사용할 가능성이 높다는 특성

예:

```c
int sum = 0;

for (int i = 0; i < 100; i++) {
    sum += i;
}
```

* 반복문이 실행되는 동안 `sum`, `i` 등의 값이 반복적으로 사용
* 최근 사용한 데이터를 빠른 저장 공간에 유지하면 접근 비용 감소 가능

```text
최근 사용
   ↓
다시 사용할 가능성 높음
   ↓
빠른 저장 공간에 유지
```

### 공간적 지역성 — Spatial Locality

* 특정 메모리 위치를 사용하면 그 주변 위치도 가까운 미래에 사용할 가능성이 높다는 특성

예:

```c
int arr[100];

for (int i = 0; i < 100; i++) {
    sum += arr[i];
}
```

* 배열의 원소는 일반적으로 메모리에 연속적으로 배치
* `arr[0]`, `arr[1]`, `arr[2]`처럼 순차 접근 시 주변 데이터를 함께 활용 가능

```text
현재 주소 접근
     ↓
인접 주소도 곧 접근할 가능성 높음
     ↓
주변 데이터까지 함께 활용
```

* 지역성의 자세한 내용은 이후 Memory Hierarchy에서 다시 학습

---

## 캐시의 계층 구조

* 현대 시스템에서는 하나의 캐시만 사용하는 것이 아니라 여러 단계의 캐시 사용
* 일반적으로 L1, L2, L3 Cache로 구성

```text
CPU
 ↓
L1 Cache
 ↓
L2 Cache
 ↓
L3 Cache
 ↓
Main Memory
```

* CPU와 가까울수록 일반적으로

  * 더 빠름
  * 더 작음

* CPU에서 멀어질수록 일반적으로

  * 더 느림
  * 더 큼

### L1 Cache

* CPU 코어와 가장 가까운 캐시
* 매우 빠르지만 작은 용량
* 명령어와 데이터를 위한 캐시가 분리되는 구조가 흔함

### L2 Cache

* L1보다 일반적으로 큰 용량
* 접근 속도는 L1보다 상대적으로 느림
* L1에서 필요한 데이터를 찾지 못했을 때 다음으로 확인하는 계층

### L3 Cache

* L2보다 일반적으로 큰 용량
* 접근 속도는 L1, L2보다 상대적으로 느림
* 여러 CPU 코어가 공유하는 구조가 흔함
* 실제 구성은 프로세서 아키텍처에 따라 달라질 수 있음

---

## 개발할 때 왜 중요한가

### 프로그램 성능은 연산 속도만으로 결정되지 않음

* CPU의 계산 속도가 빨라도 필요한 데이터가 늦게 도착하면 전체 실행 시간 증가
* 실제 프로그램 성능은 연산 비용과 데이터 접근 비용의 영향을 함께 받음

```text
연산 비용
   +
데이터 접근 비용
   ↓
실제 프로그램 성능
```

---

### 메모리 접근 패턴이 중요함

* 동일한 계산을 수행하더라도 데이터에 접근하는 순서에 따라 캐시 활용 정도 차이 발생
* 지역성이 좋은 코드는 자주 사용하는 데이터가 캐시에 남아 있을 가능성이 높음
* 결과적으로 느린 메인 메모리 접근 횟수 감소 가능

---

### 이후 학습과 연결

* 캐시는 이후 학습할 다음 내용의 기반

  * Memory Hierarchy
  * Cache Hit / Miss
  * Cache-Friendly Code
  * Program Optimization

* 지금 단계에서는 캐시의 세부 구현보다 **왜 필요한지와 어떤 원리로 효과를 얻는지 이해하는 것이 핵심**

## 1.4와의 연결

* 1.4에서는 `hello` 프로그램 실행 과정에서 코드와 데이터가 여러 하드웨어 구성 요소 사이를 이동한다는 점 학습
* 1.5에서는 이러한 데이터 이동이 왜 성능 비용이 되는지 확인
* 그리고 CPU와 메인 메모리 사이의 속도 차이를 줄이기 위해 캐시가 사용된다는 점으로 연결

```text
1.4
프로그램 실행
   ↓
데이터 이동
   ↓
1.5
CPU와 Memory의 속도 차이
   ↓
Cache 사용
```

---

## 정리

* 프로그램 실행 과정에서는 코드와 데이터가 여러 장치 사이를 계속 이동
* 이러한 데이터 이동에는 실제 비용 발생
* CPU와 메인 메모리 사이의 속도 차이는 프로그램 성능의 주요 병목 중 하나
* 캐시는 CPU 가까이에 위치한 작고 빠른 저장 공간
* 자주 사용할 가능성이 높은 데이터를 보관하여 메인 메모리 접근 횟수 감소
* 캐시가 효과적으로 동작할 수 있는 중요한 이유는 프로그램의 **지역성(Locality)**

```text
프로그램 실행
     ↓
데이터 이동 발생
     ↓
CPU와 Memory의 속도 차이
     ↓
CPU 대기 발생
     ↓
Cache 사용
     ↓
데이터 접근 비용 감소
```

> **캐시의 핵심 목적은 자주 사용하는 데이터를 CPU 가까이에 보관하여 느린 메모리 접근으로 인한 대기 시간을 줄이는 것.**
