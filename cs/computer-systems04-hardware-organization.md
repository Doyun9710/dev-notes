# 1.4 프로세서는 메모리에 저장된 명령어를 읽고 실행함

> Processors Read and Interpret Instructions Stored in Memory

## 핵심 개념

* 실행 파일이 생성되었다고 해서 프로그램이 바로 실행되는 것은 아님
* 프로그램 실행을 위해 실행 파일의 코드와 데이터가 **메인 메모리(Main Memory)** 에 적재되어야 함
* CPU는 메모리에 저장된 기계어 명령어를 하나씩 읽고 실행
* 이 과정에서 다음 주요 하드웨어 구성 요소가 함께 동작

  * 버스(Bus)
  * 입출력 장치(I/O Device)
  * 메인 메모리(Main Memory)
  * 프로세서(Processor)

```text
I/O Device
    ↕
   Bus
    ↕
Main Memory
    ↕
Processor
```

---

## 1. 컴퓨터 시스템의 주요 하드웨어 구성 요소

### 버스 — Bus

* 컴퓨터 내부의 여러 구성 요소 사이에서 **데이터와 제어 정보를 전달하는 통로**
* CPU, 메모리, 입출력 장치 등을 서로 연결
* 일반적으로 여러 비트의 데이터를 한 번에 전달하도록 구성
* 한 번에 전달되는 데이터의 크기는 시스템의 버스 구조에 따라 달라질 수 있음

> 버스가 항상 CPU의 워드 크기인 32비트 또는 64비트 단위로만 데이터를 전달한다고 이해하는 것은 부정확함

---

### 입출력 장치 — I/O Devices

* 컴퓨터 시스템과 외부 환경을 연결하는 장치

대표적인 예:

* 키보드

* 마우스

* 디스플레이

* 디스크

* 네트워크 장치

* 각 장치는 **컨트롤러(Controller)** 또는 **어댑터(Adapter)** 를 통해 시스템 버스와 연결

```text
Keyboard
   ↓
Controller
   ↓
  Bus
```

* 컨트롤러

  * 장치 자체 또는 시스템 내부에서 장치의 동작을 제어하는 구성 요소

* 어댑터

  * 시스템의 입출력 버스에 장치를 연결하기 위한 인터페이스 역할

---

### 메인 메모리 — Main Memory

* 프로그램 실행 중 필요한 **코드와 데이터를 임시로 저장하는 공간**
* CPU가 실행할 기계어 명령어 역시 메모리에 존재

물리적 관점:

* 주로 **DRAM(Dynamic Random Access Memory)** 으로 구성

논리적 관점:

* 연속된 바이트들의 배열로 이해 가능

```text
Memory

Address
1000  → data
1001  → data
1002  → instruction
1003  → instruction
...
```

* CPU는 메모리 주소를 이용하여 필요한 명령어나 데이터에 접근

---

### 프로세서 — Processor

* CPU(Central Processing Unit)라고도 부름
* 메인 메모리에 저장된 기계어 명령어를 해석하고 실행하는 핵심 장치

주요 구성 요소:

* Program Counter
* Register File
* ALU

---

### Program Counter — PC

* CPU 내부에 존재하는 특수한 레지스터
* **다음에 실행할 명령어의 주소를 나타냄**
* CPU가 명령어를 실행함에 따라 계속 변경

```text
PC
 ↓
Memory Address
 ↓
Instruction
```

* CS:APP의 단순화된 모델에서는 CPU가 PC가 가리키는 명령어를 반복적으로 실행한다고 이해 가능

---

### Register File

* CPU 내부에 존재하는 소규모의 매우 빠른 저장 공간
* 여러 개의 레지스터(Register)로 구성
* 연산에 필요한 데이터나 중간 결과 등을 임시 저장

```text
Main Memory
     ↓
 Register
     ↓
    ALU
```

* 메인 메모리에 직접 접근하는 것보다 훨씬 빠른 저장 공간

---

### ALU — Arithmetic Logic Unit

* **산술 및 논리 연산을 수행하는 장치**

대표적인 연산:

* 덧셈

* 뺄셈

* AND

* OR

* 비교

* 주소 계산

* 보통 레지스터에 저장된 값을 이용하여 연산 수행

---

## 2. CPU의 명령어 실행 과정

* CPU는 프로그램이 실행되는 동안 PC가 가리키는 명령어를 계속 처리
* 개념적으로 다음 흐름으로 이해 가능

```text
Fetch
  ↓
Decode
  ↓
Execute
  ↓
PC Update
  ↓
다음 Instruction
```

### Fetch — 인출

* PC가 가리키는 메모리 주소에서 명령어를 읽음

```text
PC
 ↓
Main Memory
 ↓
Instruction
```

---

### Decode — 해석

* 가져온 명령어가 어떤 작업을 의미하는지 해석
* 어떤 레지스터나 데이터가 필요한지 결정

---

### Execute — 실행

* 명령어가 요구하는 실제 작업 수행

예:

* 레지스터 사이의 데이터 이동
* 메모리에서 데이터 읽기
* 메모리에 데이터 저장
* 산술 및 논리 연산
* 조건에 따른 실행 흐름 변경

---

### PC Update

* 현재 명령어 실행이 끝난 뒤 PC를 다음 실행 위치로 변경
* 일반적인 경우 다음 명령어로 이동
* 분기나 함수 호출이 발생하면 다른 주소로 변경될 수도 있음

---

## 3. `hello` 프로그램을 실행하면 어떻게 동작하는가

셸에서 다음 명령어를 입력한다고 가정:

```bash
./hello
```

전체 흐름을 단순화하면 다음과 같음.

```text
Keyboard
   ↓
Shell
   ↓
Main Memory
   ↑
 Disk
   ↓
Processor
   ↓
Display
```

---

### 1. 명령어 입력

* 사용자가 키보드로 `./hello` 입력
* 키보드에서 입력된 문자가 시스템으로 전달
* 셸이 입력 내용을 읽어 메모리에 저장

```text
Keyboard
   ↓
I/O
   ↓
Memory
   ↓
Shell
```

* Enter 입력 후 셸이 명령어 입력 완료를 인식

---

### 2. 실행 파일을 메모리에 적재

* 셸이 `hello` 프로그램을 실행하도록 운영체제에 요청
* 디스크에 저장되어 있던 `hello` 실행 파일의 코드와 데이터를 메인 메모리로 적재

```text
Disk
  ↓
Main Memory
```

* 현대 시스템에서는 DMA(Direct Memory Access) 등을 이용하여 대량의 데이터를 CPU가 직접 하나씩 복사하지 않고 장치와 메모리 사이에서 전송 가능

---

### 3. CPU가 명령어 실행

* 프로그램이 메모리에 적재되면 CPU가 `hello`의 명령어를 실행하기 시작
* PC가 실행할 명령어의 위치를 가리킴

```text
PC
 ↓
hello의 Machine Instruction
 ↓
Execute
```

* CPU는 프로그램이 종료될 때까지 필요한 명령어를 차례로 실행

---

### 4. 문자열 출력

프로그램에 다음 문자열이 있다고 가정:

```text
hello, world
```

* 문자열 데이터는 실행 중 메모리에 존재
* CPU가 프로그램의 명령어에 따라 해당 데이터를 읽고 출력 작업 수행
* 결과적으로 출력 장치를 통해 사용자가 문자열을 확인

단순화하면:

```text
Main Memory
     ↓
Processor
     ↓
I/O System
     ↓
 Display
```

---

## 데이터 이동 관점에서 바라보기

`hello` 프로그램 실행 과정에서는 동일한 데이터가 여러 하드웨어 구성 요소 사이를 이동함.

```text
Keyboard
   ↓
Main Memory
   ↑
 Disk
   ↓
Processor
   ↓
Display
```

* 명령어 입력

  * Keyboard → Memory

* 실행 파일 적재

  * Disk → Memory

* 프로그램 실행

  * Memory ↔ Processor

* 결과 출력

  * Processor → I/O → Display

* 결국 프로그램 실행은 **CPU가 계산하는 과정인 동시에 시스템 내부에서 데이터가 이동하는 과정**

---

## 개발할 때 왜 중요한가

### 프로그램 실행에는 CPU 외에도 여러 구성 요소가 관여

* 프로그램 실행을 단순히 "CPU가 코드를 실행한다"라고만 보면 실제 시스템 동작을 충분히 설명하기 어려움
* 실행 과정에서 CPU뿐 아니라 다음 요소가 함께 동작

  * 메모리
  * 디스크
  * 버스
  * I/O 장치

---

### 데이터 이동 비용이 성능에 영향을 줌

* CPU가 연산을 수행하려면 필요한 데이터가 CPU까지 전달되어야 함
* 데이터가 메모리나 디스크처럼 CPU에서 멀리 있을수록 접근 비용이 커질 수 있음
* 이후 학습할 **Cache와 Memory Hierarchy**가 필요한 이유로 연결

```text
Disk
 ↓
Memory
 ↓
Cache
 ↓
Register
 ↓
CPU
```

* 결국 프로그램 성능은 연산량뿐 아니라 **데이터를 어디에서 가져오는가**에도 크게 영향을 받음

---

### 시스템 계층을 연결해서 볼 수 있음

현재까지의 학습 내용을 연결하면 다음과 같은 흐름으로 이해 가능

```text
C Source Code
      ↓
Compilation System
      ↓
Executable
      ↓
Main Memory에 적재
      ↓
CPU가 Instruction 실행
      ↓
I/O를 통해 결과 출력
```

* `1.2`에서 배운 컴파일 과정이 **실행 파일을 만드는 과정**
* 이번 내용은 만들어진 **실행 파일이 실제 하드웨어에서 실행되는 과정**
* 소스 코드와 하드웨어 동작이 처음으로 연결되는 지점

---

## 정리

* 컴퓨터 시스템은 크게 버스, 입출력 장치, 메인 메모리, 프로세서로 구성
* 메인 메모리는 실행 중인 프로그램의 코드와 데이터를 저장
* CPU는 PC가 가리키는 명령어를 읽고 실행
* CPU 내부에서는 레지스터와 ALU를 이용하여 데이터 처리
* `hello` 프로그램을 실행하면 다음 과정 발생

```text
명령어 입력
   ↓
실행 파일 메모리 적재
   ↓
CPU의 명령어 실행
   ↓
출력 장치로 결과 전달
```

* 프로그램 실행은 단순한 CPU 연산이 아니라 **메모리와 I/O 장치 사이에서 데이터가 지속적으로 이동하는 과정**
* 이러한 데이터 이동 비용을 줄이기 위해 다음 학습 내용인 **캐시(Cache)** 가 중요한 역할을 하게 됨

> **프로그램은 메모리에 적재되고, CPU는 메모리에 저장된 명령어를 하나씩 읽고 실행하면서 프로그램을 동작시킴.**
