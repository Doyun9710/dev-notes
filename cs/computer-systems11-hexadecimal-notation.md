# 2.1.1 비트 패턴을 간결하게 표현하는 16진수

> Hexadecimal Notation

## 핵심 개념

* 컴퓨터의 정보는 실제로 `0`과 `1`로 이루어진 비트 형태로 저장됨
* 하지만 긴 이진수는 사람이 읽고 작성하기 불편함

예:

```text
0110100010010101
```

* 비트 수가 증가할수록 다음 문제가 발생

  * 값의 빠른 식별이 어려움
  * 특정 비트 위치 확인이 어려움
  * 작성 과정에서 오류 발생 가능성 증가

* 이를 해결하기 위해 시스템 프로그래밍에서는 **16진수(Hexadecimal)** 표기법을 널리 사용

```text
Binary
0110 1000 1001 0101

Hexadecimal
0x6895
```

* 핵심은 **16진수가 새로운 데이터 저장 방식이 아니라 비트 패턴을 사람이 다루기 쉽게 나타내는 표기법이라는 점**

---

## 16진수가 비트 표현에 적합한 이유

* 16은 다음과 같이 2의 거듭제곱

```text
16 = 2⁴
```

* 따라서 **4개의 비트가 하나의 16진수 숫자와 정확히 대응**

```text
0000 ~ 1111
      ↓
  0 ~ F
```

* 4비트의 묶음을 **니블(Nibble)** 이라고 부르기도 함

```text
1 hexadecimal digit
        =
      4 bits
```

* 일반적인 1바이트는 8비트이므로 16진수 두 자리로 표현 가능

```text
1 Byte
= 8 bits
= 2 hexadecimal digits
```

예:

```text
1111 1010
   ↓
   F    A
   ↓
  0xFA
```

* 이러한 대응 관계 때문에 16진수는 메모리 주소, 기계어, 비트 마스크 등의 표현에서 특히 유용

---

## 16진수의 기본 구성

16진수는 총 16개의 기호 사용.

| 16진수 | 10진수 | 2진수    |
| ---- | ---: | ------ |
| `0`  |    0 | `0000` |
| `1`  |    1 | `0001` |
| `2`  |    2 | `0010` |
| `3`  |    3 | `0011` |
| `4`  |    4 | `0100` |
| `5`  |    5 | `0101` |
| `6`  |    6 | `0110` |
| `7`  |    7 | `0111` |
| `8`  |    8 | `1000` |
| `9`  |    9 | `1001` |
| `A`  |   10 | `1010` |
| `B`  |   11 | `1011` |
| `C`  |   12 | `1100` |
| `D`  |   13 | `1101` |
| `E`  |   14 | `1110` |
| `F`  |   15 | `1111` |

* `A`~`F`는 대문자와 소문자 모두 사용 가능

```text
0xFA1D
0xfa1d
0xFa1D
```

* 위 표현은 모두 동일한 숫자값

### C에서의 16진수 표기

* C에서는 16진수 정수 상수 앞에 `0x` 또는 `0X` 접두사 사용

```c
0x173A
0X173A
0xff
0x03
```

* 접두사를 통해 해당 숫자가 16진수임을 표시

---

## 16진수를 이진수로 변환

* 각 16진수 숫자를 대응하는 **4비트 이진수**로 변환하면 됨

예:

```text
0x173A
```

각 자리 변환:

```text
1 → 0001
7 → 0111
3 → 0011
A → 1010
```

따라서:

```text
0x173A

→ 0001 0111 0011 1010
```

* 16진수 한 자리와 4비트가 정확히 대응하기 때문에 별도의 복잡한 계산 불필요

> 단, 위 표현이 `0x173A`라는 값 자체가 항상 16비트 크기로 저장된다는 의미는 아님. 단순히 네 개의 16진수 자리를 각각 4비트로 펼쳐 표현한 결과.

---

## 이진수를 16진수로 변환

* 이진수는 **오른쪽, 즉 최하위 비트(Least Significant Bit) 쪽부터 4비트씩 그룹화**

예:

```text
11110010101
```

오른쪽부터 나누면:

```text
111 / 1001 / 0101
```

가장 왼쪽 그룹이 4비트보다 짧으므로 앞쪽을 `0`으로 채움.

```text
0111 / 1001 / 0101
```

각 그룹을 16진수로 변환:

```text
0111 → 7
1001 → 9
0101 → 5
```

따라서:

```text
11110010101₂
→ 0x795
```

* 왼쪽에 추가된 `0`은 숫자의 값을 변경하지 않음

```text
111
=
0111
```

## 2의 거듭제곱을 16진수로 빠르게 표현하기

16진수와 비트의 대응 관계를 이용하면 $2^n$ 형태의 값을 빠르게 표현 가능.

$n$을 다음 형태로 표현한다고 가정.

```text
n = i + 4j

0 ≤ i ≤ 3
```

그러면:

```text
2ⁿ
= 2ⁱ × 2⁴ʲ
= 2ⁱ × 16ʲ
```

따라서 16진수에서는

* 첫 번째 숫자 → $2^i$
* 뒤에 붙는 `0`의 개수 → $j$

형태로 표현 가능.

$2^i$에 대응하는 값:

| $i$ | $2^i$ | 16진수 첫 자리 |
| --: | ----: | --------- |
|   0 |     1 | `1`       |
|   1 |     2 | `2`       |
|   2 |     4 | `4`       |
|   3 |     8 | `8`       |

### 예: $2^{11}$

```text
11 = 3 + 4 × 2
```

따라서:

```text
i = 3
j = 2
```

첫 번째 숫자:

```text
2³ = 8
```

뒤에 `0`을 두 개 추가:

```text
0x800
```

결과:

```text
2¹¹
= 2048
= 0x800
```

다른 예:

```text
2⁸  = 0x100
2¹² = 0x1000
2¹⁶ = 0x10000

2⁷  = 0x80
2¹⁵ = 0x8000
```

## 개발할 때 왜 중요한가

### 비트 패턴을 읽기 쉬워짐

* 시스템 수준의 데이터는 긴 비트 패턴으로 나타나는 경우가 많음
* 이를 이진수 그대로 표현하면 가독성이 크게 떨어짐

```text
1111111111111111
```

16진수에서는:

```text
0xFFFF
```

* 동일한 정보를 훨씬 짧게 표현 가능

---

### 메모리 주소 표현

* 메모리 주소는 일반적으로 16진수로 표시

예:

```text
0x7fffffffe120
```

* 이후 포인터와 가상 메모리를 학습할 때 계속 등장하는 표현

---

### 비트 마스크와 비트 연산

특정 비트 집합을 나타낼 때 16진수 사용이 편리함.

```c
unsigned mask = 0xFF;
```

이를 이진수로 보면:

```text
0xFF
=
1111 1111
```

* 어떤 비트가 `1`인지 빠르게 확인 가능
* 이후 `&`, `|`, `^`, `~`, shift 연산 학습과 직접 연결

---

### 기계 수준의 프로그램 분석

* 기계어 명령어 자체도 결국 비트 패턴
* 실제 도구에서는 이를 주로 16진수로 출력

예:

```text
48 89 e5
```

* Chapter 3의 기계 수준 프로그램 표현에서 반복적으로 사용될 표기 방식

## 이후 학습과의 연결

Chapter 1에서는 모든 정보가 결국 비트로 표현된다는 관점 학습.

```text
Information
    ↓
   Bits
```

이번 절에서는 이러한 비트를 개발자가 효율적으로 읽고 표현하는 방법으로 16진수 학습.

```text
Bits
 ↓
Binary Representation
 ↓
Hexadecimal Notation
```

이후 Chapter 2에서는 같은 비트 패턴을 실제 데이터로 해석하는 방법 학습 예정.

```text
Hexadecimal Notation
        ↓
Data Representation
        ↓
Unsigned Integer
        ↓
Signed Integer
        ↓
Floating Point
```

* 따라서 16진수는 단순한 진법 계산 기술이라기보다 **시스템에서 사용되는 비트 표현을 읽기 위한 기본 표기법**

---

## 정리

* 컴퓨터의 실제 정보 표현은 비트 기반
* 긴 이진수는 사람이 읽고 다루기 어려움
* 16진수는 비트 패턴을 간결하게 표현하기 위한 표기법
* $16 = 2^4$이므로 **16진수 한 자리와 4비트가 정확히 대응**
* 1바이트는 8비트이므로 일반적으로 16진수 두 자리로 표현 가능
* 이진수와 16진수 사이에서는 4비트 단위로 직접 변환 가능
* 메모리 주소, 비트 연산, 기계어 등을 다룰 때 지속적으로 사용되는 표현 방식

> **16진수의 핵심은 새로운 데이터 표현 방식이 아니라, 비트 패턴을 사람이 효율적으로 읽고 다루기 위한 표기법이라는 점.**
