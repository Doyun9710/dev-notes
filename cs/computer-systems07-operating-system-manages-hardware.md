# 1.7 운영체제는 하드웨어를 관리함

> The Operating System Manages the Hardware

## 핵심 개념

* 운영체제(OS)는 **응용 프로그램과 하드웨어 사이에 위치하는 소프트웨어 계층**
* 응용 프로그램이 CPU, 메모리, I/O 장치를 직접 제어하지 않도록 중간에서 관리
* 주요 목적은 크게 두 가지

  * 잘못 동작하는 프로그램으로부터 하드웨어와 다른 프로그램 보호
  * 복잡한 하드웨어를 쉽게 사용할 수 있도록 추상화된 인터페이스 제공

```text
Application
    ↓
Operating System
    ↓
Hardware
```

* 운영체제가 제공하는 대표적인 추상화

  * Process
  * Thread
  * Virtual Memory
  * File

---

## 운영체제가 필요한 이유

### 하드웨어 보호

* 여러 프로그램이 동시에 CPU, 메모리, I/O 장치를 사용
* 응용 프로그램이 하드웨어를 직접 제어하면 다른 프로그램의 실행을 방해하거나 시스템 전체에 문제 발생 가능
* 운영체제가 하드웨어 접근을 통제하여 프로그램 사이의 격리 제공

```text
Application
    ↓
Operating System
    ↓
CPU / Memory / I/O
```

---

### 하드웨어 추상화

* 실제 하드웨어는 장치마다 동작 방식과 제어 방법이 다름
* 운영체제는 이러한 차이를 감추고 프로그램에 일관된 사용 방법 제공

```text
복잡한 Hardware
      ↓
Operating System
      ↓
단순한 추상화
```

대표적인 관계:

| 추상화            | 주로 추상화하는 대상       |
| -------------- | ----------------- |
| Process        | CPU와 시스템 자원       |
| Virtual Memory | Main Memory       |
| File           | I/O Device        |
| Thread         | Process 내부의 실행 흐름 |

---

## 1. 프로세스 — Process

* **실행 중인 프로그램에 대한 운영체제의 추상화**
* 각 프로그램이 마치 시스템을 독점적으로 사용하는 것처럼 보이게 함
* 프로세스마다 독립적인 실행 상태와 주소 공간 제공

```text
Process A ─┐
Process B ─┼─→ CPU
Process C ─┘
```

### 동시 실행

* 하나의 CPU 코어에서도 여러 프로세스를 빠르게 번갈아 실행 가능
* 사용자는 여러 프로그램이 동시에 실행되는 것처럼 인식
* 멀티코어 시스템에서는 실제로 여러 프로세스가 동시에 실행될 수도 있음

---

### Context

* 운영체제가 프로세스를 다시 실행하기 위해 기억해야 하는 실행 상태

대표적인 정보:

* Program Counter
* Register 상태
* 메모리 관련 정보
* 열린 파일 등의 시스템 자원 상태

---

### Context Switch

* CPU가 현재 실행 중인 프로세스를 멈추고 다른 프로세스를 실행하는 과정
* 현재 프로세스의 상태를 저장한 뒤 다음 프로세스의 상태를 복원

```text
Process A 실행
      ↓
상태 저장
      ↓
Process B 상태 복원
      ↓
Process B 실행
```

* 운영체제는 이러한 전환을 통해 여러 프로그램이 CPU를 공유하도록 관리

---

## 2. 쓰레드 — Thread

* 프로세스 내부에서 실행되는 **하나의 제어 흐름**
* 하나의 프로세스는 하나 이상의 쓰레드로 구성 가능

```text
Process
 ├─ Thread 1
 ├─ Thread 2
 └─ Thread 3
```

### 쓰레드가 공유하는 자원

같은 프로세스에 속한 쓰레드는 일반적으로 다음 자원을 공유

* 코드
* 전역 데이터
* Heap
* 열린 파일 등의 프로세스 자원

반면 각 쓰레드는 독립적인 실행 상태 보유

* Program Counter
* Register 상태
* Stack

```text
Process
│
├─ Shared
│   ├─ Code
│   ├─ Global Data
│   └─ Heap
│
├─ Thread 1
│   └─ Stack
│
└─ Thread 2
    └─ Stack
```

### 특징

* 같은 주소 공간을 공유하므로 쓰레드 사이의 데이터 공유가 비교적 쉬움
* 프로세스를 새로 생성하는 것보다 상대적으로 적은 자원으로 여러 실행 흐름 구성 가능
* 멀티코어 환경에서는 여러 쓰레드를 병렬로 실행 가능

---

## 3. 가상 메모리 — Virtual Memory

* 각 프로세스에 **독립적인 주소 공간이 존재하는 것처럼 보이게 하는 추상화**
* 프로세스는 실제 물리 메모리의 배치를 직접 알 필요 없이 가상 주소를 사용

```text
Process A
Virtual Address Space
        ↓
Operating System + Hardware
        ↓
Physical Memory

Process B
Virtual Address Space
        ↓
Operating System + Hardware
        ↓
Physical Memory
```

* 각 프로세스는 자신만의 메모리를 가지고 있다고 인식
* 실제 물리 메모리는 여러 프로세스가 운영체제의 관리 아래 공유

---

## 가상 주소 공간의 기본 구조

일반적인 프로세스의 가상 주소 공간은 다음과 같은 영역으로 구성

```text
높은 주소
┌─────────────────────┐
│ Kernel Virtual Memory│
├─────────────────────┤
│ Stack               │
│        ↓            │
├─────────────────────┤
│ Shared Libraries    │
├─────────────────────┤
│        ↑            │
│ Heap                │
├─────────────────────┤
│ Data                │
├─────────────────────┤
│ Code                │
└─────────────────────┘
낮은 주소
```

### Code

* 프로그램의 기계어 명령어가 저장되는 영역

### Data

* 전역 변수와 정적 데이터 등이 저장되는 영역

### Heap

* 실행 중 동적으로 할당되는 메모리 영역

예:

```c
int *p = malloc(sizeof(int));
```

* 일반적으로 낮은 주소에서 높은 주소 방향으로 확장

### Shared Libraries

* 여러 프로그램에서 사용할 수 있는 라이브러리 코드와 데이터가 매핑되는 영역
* C 표준 라이브러리 등이 대표적인 예

### Stack

* 함수 호출과 관련된 데이터를 저장하는 영역

대표적으로:

* 지역 변수

* 함수 호출 정보

* 일부 매개변수

* 반환과 관련된 정보

* 일반적으로 높은 주소에서 낮은 주소 방향으로 확장

### Kernel Virtual Memory

* 운영체제 커널을 위한 영역
* 일반적인 사용자 프로그램이 직접 접근할 수 없음

---

## 4. 파일 — File

* 운영체제에서 파일은 기본적으로 **바이트의 연속(Sequence of Bytes)** 으로 보는 추상화
* 프로그램은 실제 저장장치의 내부 구조를 직접 알 필요 없이 파일 인터페이스를 통해 데이터 사용

```text
Program
   ↓
File Interface
   ↓
Operating System
   ↓
I/O Device
```

### Unix 계열 시스템의 파일 추상화

* Unix 계열 운영체제에서는 많은 I/O 자원을 파일과 유사한 인터페이스로 다룸

* 대표적인 예

  * 일반 파일
  * 터미널
  * 장치
  * 파이프
  * 소켓

* 프로그램은 `read`, `write`와 같은 공통 인터페이스를 이용하여 다양한 I/O 처리 가능

```c
read(...);
write(...);
```

* 장치마다 서로 다른 세부 제어 방식을 프로그램이 직접 처리하지 않아도 된다는 장점

---

## 추상화 관계

```text
Application
    │
    ├─ Process
    ├─ Thread
    ├─ Virtual Memory
    └─ File
         ↓
Operating System
         ↓
Hardware
    │
    ├─ CPU
    ├─ Main Memory
    └─ I/O Devices
```

| OS 추상화         | 핵심 의미                        |
| -------------- | ---------------------------- |
| Process        | 실행 중인 프로그램에 시스템 자원을 제공하는 추상화 |
| Thread         | 프로세스 내부의 실행 흐름               |
| Virtual Memory | 각 프로세스에 독립적인 주소 공간 제공        |
| File           | I/O 데이터를 바이트의 연속으로 다루는 추상화   |

---

## 개발할 때 왜 중요한가

### 프로세스와 쓰레드의 차이 이해

* 서버, 백엔드, GUI 프로그램 등에서는 여러 작업을 동시에 처리해야 하는 경우가 많음
* 프로세스와 쓰레드의 자원 공유 방식 차이를 이해하면 동시성 프로그램 설계의 기반 확보

---

### 메모리 문제 분석

* 프로그램의 메모리가 Code, Heap, Stack 등의 영역으로 구성된다는 사실은 다양한 문제와 연결

예:

* Stack Overflow

* Memory Leak

* Buffer Overflow

* 잘못된 포인터 접근

* 이후 가상 메모리와 메모리 관리 학습의 기반

---

### 운영체제 API 이해

* 개발자가 사용하는 파일 입출력이나 프로세스 생성 등의 기능은 결국 운영체제가 제공하는 인터페이스
* 시스템 프로그래밍에서는 이러한 추상화 아래에서 실제로 어떤 동작이 발생하는지 이해하는 것이 중요

---

## 정리

* 운영체제는 응용 프로그램과 하드웨어 사이에서 시스템 자원을 관리
* 프로그램이 하드웨어를 직접 제어하지 않도록 보호 기능 제공
* 복잡한 하드웨어를 쉽게 사용할 수 있도록 여러 추상화 제공

```text
Operating System
      │
      ├─ Process
      ├─ Thread
      ├─ Virtual Memory
      └─ File
```

* Process

  * 실행 중인 프로그램의 추상화
* Thread

  * 프로세스 내부의 실행 흐름
* Virtual Memory

  * 각 프로세스에 독립적인 주소 공간 제공
* File

  * I/O를 바이트의 연속이라는 형태로 추상화

> **운영체제의 핵심 역할은 복잡한 하드웨어를 직접 노출하지 않고, 프로그램이 안전하고 일관된 방식으로 시스템 자원을 사용할 수 있도록 추상화를 제공하는 것.**
