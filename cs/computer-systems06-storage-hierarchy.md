# 1.6 저장장치는 계층 구조를 이룸

> Storage Devices Form a Hierarchy

## 핵심 개념

* 컴퓨터의 저장장치는 하나의 종류로만 구성되지 않음
* 속도, 용량, 비용이 서로 다른 여러 저장장치를 계층적으로 조합하여 사용
* 이러한 구조를 **메모리 계층 구조(Memory Hierarchy)** 라고 함
* 상위 계층일수록 빠르고 작으며 비트당 비용이 높음
* 하위 계층일수록 느리지만 크고 비트당 비용이 낮음
* 핵심 아이디어는 **상위 계층이 바로 아래 계층의 데이터를 일부 저장하는 캐시 역할 수행**

```text
        빠름 / 작음 / 비쌈
               ↑

L0     Registers
L1     L1 Cache
L2     L2 Cache
L3     L3 Cache
L4     Main Memory
L5     Local Storage
L6     Remote Storage

               ↓
        느림 / 큼 / 저렴
```

---

## 메모리 계층 구조의 특징

상위 계층으로 갈수록 일반적으로 다음 특징 존재

* 접근 속도 증가
* 용량 감소
* 비트당 비용 증가
* CPU와 가까운 위치

하위 계층으로 갈수록 일반적으로 다음 특징 존재

* 접근 속도 감소
* 용량 증가
* 비트당 비용 감소
* CPU와 먼 위치

```text
위쪽
→ 빠름
→ 작음
→ 비쌈

아래쪽
→ 느림
→ 큼
→ 저렴
```

---

## L0 — Register

* CPU 내부에 존재하는 가장 빠른 저장 공간
* CPU가 연산에 직접 사용하는 데이터 저장
* 매우 작은 용량
* 일반적으로 하나의 레지스터는 시스템의 워드 크기와 관련된 크기를 가짐

```text
ALU
 ↕
Registers
```

* 메모리 계층 구조에서 가장 상위에 위치
* CPU 명령어가 직접 접근하는 저장 공간

---

## L1 ~ L3 — Cache

* CPU와 메인 메모리 사이에 존재하는 고속 저장 공간
* 일반적으로 SRAM 기반
* 자주 사용할 가능성이 높은 데이터를 메인 메모리보다 CPU 가까이에 보관

```text
CPU
 ↓
L1 Cache
 ↓
L2 Cache
 ↓
L3 Cache
 ↓
Main Memory
```

### L1 Cache

* CPU 코어와 가장 가까운 캐시
* 매우 빠르지만 작은 용량
* 현대 프로세서에서는 다음과 같이 분리되는 경우가 많음

  * Instruction Cache
  * Data Cache

### L2 Cache

* L1보다 일반적으로 큰 용량
* L1보다 접근 속도는 상대적으로 느림
* L1에서 필요한 데이터를 찾지 못했을 때 다음으로 확인하는 계층

### L3 Cache

* L2보다 일반적으로 더 큰 용량
* 접근 속도는 L1, L2보다 상대적으로 느림
* 여러 CPU 코어가 공유하는 구조가 흔함
* 세부 구조는 프로세서 아키텍처에 따라 달라질 수 있음

---

## L4 — Main Memory

* 일반적으로 DRAM으로 구성
* 실행 중인 프로그램의 코드와 데이터 저장
* CPU Cache보다 큰 용량 제공
* Cache보다 접근 속도는 느림

```text
CPU
 ↓
Cache
 ↓
Main Memory
```

* 실행 파일이 디스크에서 메모리로 적재된 이후 CPU가 명령어와 데이터를 읽는 주요 공간
* 상위 Cache 계층에 필요한 데이터 공급

---

## L5 — Local Storage

* SSD, HDD 등의 로컬 보조 저장장치
* 메인 메모리보다 훨씬 큰 용량 제공
* 전원이 꺼져도 데이터 유지 가능
* 접근 속도는 메인 메모리보다 훨씬 느림

대표적인 저장 대상

* 실행 파일
* 문서
* 데이터베이스 파일
* 운영체제 파일
* 프로그램 데이터

```text
SSD / HDD
    ↓
Main Memory
    ↓
Cache
    ↓
CPU
```

---

## L6 — Remote Storage

* 네트워크를 통해 접근하는 원격 저장장치
* 로컬 시스템 외부에 존재하는 데이터 저장 공간

대표적인 예

* 원격 서버

* Network File System

* 분산 저장 시스템

* 클라우드 스토리지

* 네트워크 통신 과정이 추가되므로 로컬 저장장치보다 높은 접근 비용 발생 가능

```text
Remote Storage
      ↓
   Network
      ↓
Local System
```

---

## 계층 사이의 관계

* 메모리 계층 구조에서 가장 중요한 개념은 **캐싱(Caching)**
* 상위 계층이 바로 아래 계층에 있는 데이터의 일부를 저장
* CPU가 자주 사용하는 데이터일수록 가능한 한 상위 계층에 위치하는 것이 유리

```text
Registers
   ↑
L1 Cache
   ↑
L2 Cache
   ↑
L3 Cache
   ↑
Main Memory
   ↑
Local Storage
   ↑
Remote Storage
```

* 예를 들어 L1 Cache는 L2 Cache에 존재하는 데이터 일부를 저장
* L2 Cache는 더 아래 계층에 있는 데이터 일부를 저장
* Main Memory 역시 디스크에 존재하는 데이터 일부를 현재 실행에 필요한 형태로 보관

---

## 왜 하나의 저장장치만 사용하지 않는가

* 모든 저장장치를 빠른 SRAM으로 구성하는 것은 비용과 용량 측면에서 비현실적
* 반대로 모든 저장장치를 SSD나 HDD처럼 구성하면 CPU가 데이터를 기다리는 시간이 지나치게 증가
* 따라서 서로 다른 특성을 가진 저장장치를 조합하는 방식 사용

```text
빠르지만 작고 비싼 저장장치
             +
느리지만 크고 저렴한 저장장치
             ↓
       Memory Hierarchy
```

* 결과적으로 시스템은 다음 두 목표를 동시에 만족하도록 설계

  * 큰 저장 용량 확보
  * 자주 사용하는 데이터에 대한 빠른 접근

---

## 지역성과 메모리 계층

* 메모리 계층 구조가 효과적으로 동작하는 중요한 이유는 프로그램의 **지역성(Locality)**
* 최근 사용한 데이터나 주변 데이터를 다시 사용할 가능성이 높다는 특성 활용

```text
자주 사용하는 데이터
        ↓
상위 계층에 유지
        ↓
빠른 접근 가능
```

* 지역성이 좋은 프로그램은 필요한 데이터가 상위 계층에 남아 있을 가능성이 높음

* 결과적으로 느린 하위 계층에 접근하는 횟수 감소

* 지역성과 Cache Hit/Miss에 대한 상세 내용은 이후 Memory Hierarchy 학습에서 다시 다룸

---

## 개발할 때 왜 중요한가

### 프로그램 성능은 CPU 속도만으로 결정되지 않음

* CPU 연산 속도가 빨라도 필요한 데이터가 느린 저장장치에 존재하면 대기 시간 발생
* 실제 성능은 계산 비용뿐 아니라 데이터 접근 비용에도 영향 받음

```text
연산 비용
   +
데이터 접근 비용
   ↓
실제 프로그램 성능
```

---

### 데이터의 위치가 중요함

* 동일한 데이터라도 어느 계층에 존재하는지에 따라 접근 비용 차이 발생

```text
Register
   ↓
Cache
   ↓
DRAM
   ↓
SSD
   ↓
Network
```

* 아래 계층으로 내려갈수록 일반적으로 접근 비용 증가
* 자주 사용하는 데이터를 CPU 가까이에 유지하는 것이 중요

---

### 코드의 메모리 접근 방식과 연결

* 배열이나 자료구조를 어떤 순서로 접근하는지에 따라 Cache 활용 정도가 달라질 수 있음
* 지역성이 좋은 접근 패턴은 상위 메모리 계층을 효과적으로 활용 가능
* 이후 다음 학습 내용과 연결

  * Cache Hit / Miss
  * Cache-Friendly Code
  * Memory Hierarchy
  * Program Optimization

---

## 1.5와의 연결

* 1.5에서는 CPU와 메인 메모리 사이의 속도 차이를 줄이기 위해 Cache가 필요하다는 점 학습
* 1.6에서는 이 Cache 개념을 전체 저장장치 구조로 확장

```text
1.5
CPU ↔ Cache ↔ Main Memory
        ↓
1.6
Registers
   ↓
Caches
   ↓
Main Memory
   ↓
Local Storage
   ↓
Remote Storage
```

* 즉 Cache는 특정 장치 하나의 이름만을 의미하지 않음
* **빠른 상위 계층이 느린 하위 계층의 데이터를 일부 보관한다는 일반적인 시스템 설계 원리**로 이해 가능

---

## 정리

* 컴퓨터의 저장장치는 속도, 용량, 비용에 따라 계층 구조로 구성
* 상위 계층일수록 빠르고 작으며 비쌈
* 하위 계층일수록 느리지만 크고 저렴함
* 상위 계층은 바로 아래 계층의 데이터를 일부 저장하는 캐시 역할 수행
* 이러한 구조를 통해 큰 저장 용량과 빠른 접근 속도 사이의 균형 확보

```text
Registers
   ↓
L1 / L2 / L3 Cache
   ↓
Main Memory
   ↓
Local Storage
   ↓
Remote Storage
```

* 메모리 계층 구조가 효과적으로 동작하는 중요한 기반은 프로그램의 지역성
* 프로그램 성능을 이해하려면 연산 비용뿐 아니라 **데이터가 어느 저장 계층에 존재하는지**도 함께 고려할 필요

> **메모리 계층 구조의 핵심은 작고 빠른 저장장치와 크고 느린 저장장치를 조합하여, 자주 사용하는 데이터를 CPU 가까이에 유지하는 것.**
