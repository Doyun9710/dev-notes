# 1.8 시스템은 네트워크를 통해 다른 시스템과 통신함

> Systems Communicate with Other Systems Using Networks

## 핵심 개념

* 현대 컴퓨터 시스템은 독립적으로 동작하기보다 네트워크를 통해 다른 시스템과 연결되는 경우가 많음
* 개별 시스템의 관점에서 **네트워크 역시 하나의 I/O 장치로 볼 수 있음**
* 네트워크를 통해 다른 컴퓨터에 저장된 데이터와 프로그램에 접근 가능
* 결과적으로 데이터 이동 범위가 하나의 컴퓨터 내부에서 다른 컴퓨터까지 확장됨

```text
Local System
     ↓
Network Adapter
     ↓
   Network
     ↓
Network Adapter
     ↓
Remote System
```

---

## 네트워크도 하나의 I/O 장치

* 컴퓨터 내부에서 네트워크 어댑터(Network Adapter)는 I/O 장치 중 하나
* 디스크, 키보드, 디스플레이처럼 시스템의 I/O 구조를 통해 CPU 및 메인 메모리와 데이터 교환

```text
Main Memory
     ↕
   I/O Bus
     ↕
Network Adapter
     ↕
   Network
```

* 키보드

  * 외부 입력을 시스템 내부로 전달

* 디스크

  * 저장된 데이터를 메인 메모리로 전달

* 네트워크 어댑터

  * 다른 시스템에서 전달된 데이터를 현재 시스템으로 전달
  * 현재 시스템의 데이터를 다른 시스템으로 전송

* 시스템 내부의 관점에서는 네트워크 역시 **데이터가 들어오고 나가는 또 하나의 통로**

---

## 네트워크를 통한 시스템 연결

* 네트워크를 이용하면 한 시스템이 다른 시스템의 데이터나 서비스를 사용할 수 있음
* 클라이언트와 서버 간 통신을 단순화하면 다음과 같은 구조

```text
Client
  │
  │ Request
  ▼
Network Adapter
  │
  ▼
Network
  │
  ▼
Network Adapter
  │
  ▼
Server
```

* 서버의 응답은 반대 방향으로 전달

```text
Server
  │
  │ Response
  ▼
Network Adapter
  │
  ▼
Network
  │
  ▼
Network Adapter
  │
  ▼
Client
```

---

## 네트워크를 통한 데이터 이동

### 1. 클라이언트 요청

* 사용자가 클라이언트 프로그램에서 특정 작업 요청
* CPU가 요청에 필요한 데이터를 처리
* 전송할 데이터가 네트워크 어댑터를 통해 외부 네트워크로 전달

```text
Application
    ↓
Main Memory
    ↓
Network Adapter
    ↓
Network
```

---

### 2. 네트워크 전송

* 네트워크 어댑터에서 전송된 데이터가 통신망을 통해 원격 시스템으로 이동
* 실제 전송 과정에서는 여러 네트워크 장치와 통신 매체를 거칠 수 있음

예:

* Ethernet

* Wi-Fi

* Switch

* Router

* 광케이블

* 인터넷

* 프로그램 입장에서는 이러한 물리적인 전송 과정을 직접 제어할 필요 없음

---

### 3. 서버 수신

* 서버의 네트워크 어댑터가 전달된 데이터를 수신
* 수신된 데이터가 서버의 메인 메모리로 전달
* 서버 CPU가 요청 내용을 읽고 필요한 작업 수행

```text
Network
   ↓
Network Adapter
   ↓
Main Memory
   ↓
CPU
```

---

### 4. 서버의 요청 처리

* 서버 프로그램이 클라이언트의 요청에 따라 필요한 작업 수행

예:

* 파일 읽기

* 데이터베이스 조회

* 계산 수행

* 웹 페이지 생성

* 처리 결과를 다시 클라이언트에 전달할 데이터로 준비

---

### 5. 서버 응답

* 서버에서 생성한 결과가 네트워크 어댑터를 통해 클라이언트로 전송
* 클라이언트의 네트워크 어댑터가 데이터를 수신
* 수신한 데이터를 메모리에 전달
* 클라이언트 프로그램이 결과를 처리

```text
Server
  ↓
Network
  ↓
Client Memory
  ↓
Application
  ↓
Display
```

---

## `hello` 프로그램과 연결해서 보기

* CS:APP에서 사용하는 `hello` 프로그램도 네트워크를 이용하면 다른 시스템에서 실행 가능
* 로컬 터미널에서 원격 시스템에 접속하여 프로그램을 실행한다고 생각할 수 있음

전체 과정을 단순화하면 다음과 같음

```text
Local Keyboard
      ↓
Local Client
      ↓
Network
      ↓
Remote Server
      ↓
hello 실행
      ↓
Network
      ↓
Local Client
      ↓
Display
```

* 키보드 입력이 네트워크를 통해 원격 시스템으로 전달
* 원격 시스템에서 프로그램 실행
* 실행 결과가 다시 네트워크를 통해 로컬 시스템으로 전달
* 사용자 입장에서는 원격 프로그램도 로컬 프로그램과 비슷한 방식으로 사용 가능

---

## 운영체제의 I/O 추상화와 네트워크

* 이전 1.7에서 운영체제는 다양한 I/O 장치를 일관된 인터페이스로 추상화한다는 점 학습
* 네트워크 역시 이러한 I/O 시스템의 연장선에서 이해 가능

```text
Application
    ↓
OS I/O Interface
    ↓
Network
```

* Unix 계열 시스템에서는 네트워크 통신에서도 파일 I/O와 유사한 인터페이스 사용 가능
* 대표적인 추상화가 **Socket**

---

## 소켓 — Socket

* 네트워크 통신을 위한 운영체제 수준의 인터페이스
* 프로그램이 네트워크 하드웨어를 직접 제어하지 않고 데이터를 송수신할 수 있도록 추상화

개념적으로 다음과 같은 흐름

```text
Application
    ↓
Socket
    ↓
Operating System
    ↓
Network Adapter
    ↓
Network
```

* 소켓을 통해 연결이 구성된 뒤 `read()`, `write()`와 같은 I/O 인터페이스를 이용할 수 있음
* 네트워크 카드의 세부적인 하드웨어 동작을 응용 프로그램이 직접 처리할 필요 없음

> 일반 파일과 네트워크 소켓이 완전히 같은 대상이라는 의미가 아니라, Unix가 여러 I/O 자원에 공통된 읽기·쓰기 모델을 제공한다는 관점으로 이해

---

## 네트워크도 결국 데이터 이동

지금까지 학습한 내용을 연결하면 프로그램 실행의 상당 부분을 **데이터 이동**이라는 관점으로 바라볼 수 있음

```text
Disk
  ↓
Main Memory
  ↓
CPU
  ↓
Network Adapter
  ↓
Network
  ↓
Remote System
```

* 1.4

  * 시스템 내부에서 데이터 이동

* 1.5

  * 데이터 이동 비용을 줄이기 위한 Cache

* 1.6

  * 서로 다른 저장장치를 Memory Hierarchy로 구성

* 1.7

  * 운영체제가 하드웨어를 추상화하고 관리

* 1.8

  * 데이터 이동 범위가 네트워크를 통해 다른 시스템까지 확장

---

## 개발할 때 왜 중요한가

### 네트워크 프로그래밍의 기반

* 웹 서버와 클라이언트도 결국 네트워크를 통해 데이터를 주고받는 프로그램
* HTTP와 같은 고수준 프로토콜 아래에서도 실제로는 운영체제의 네트워크 I/O 기능 사용

```text
Application
    ↓
HTTP
    ↓
Socket
    ↓
Operating System
    ↓
Network
```

* 이후 네트워크 프로그래밍을 학습할 때 시스템 호출과 Socket의 역할을 이해하는 기반

---

### 로컬과 원격의 차이를 이해할 수 있음

* 함수 호출이나 메모리 접근과 달리 네트워크 통신에는 다른 시스템까지 데이터가 이동하는 과정 포함

* 따라서 다음과 같은 추가 비용과 문제가 존재 가능

* 네트워크 지연

* 연결 실패

* 패킷 손실

* 서버 장애

* 통신량 증가

* 분산 시스템에서는 **데이터가 어디에 존재하고 어디까지 이동해야 하는가**가 중요한 설계 요소

---

### 분산 시스템의 기반

* 하나의 시스템이 모든 작업을 처리할 필요 없이 여러 시스템이 네트워크로 연결되어 역할 분담 가능

대표적인 예:

* Web Application
* Cloud Computing
* Distributed Database
* Distributed File System
* Microservices

```text
Client
   ↓
Network
   ↓
Server A ─── Server B
   │             │
Database      Storage
```

* 현대 소프트웨어 인프라는 이러한 시스템 간 통신을 기반으로 구성

---

## 1.7과의 연결

* 1.7에서는 운영체제가 I/O 장치를 추상화한다는 점 학습
* 네트워크도 컴퓨터 시스템 입장에서는 I/O 장치의 하나
* 따라서 네트워크 통신 역시 운영체제가 제공하는 I/O 추상화를 통해 사용 가능

```text
1.7
Operating System
      ↓
I/O Abstraction
      ↓
File / Socket
      ↓
1.8
Network Communication
```

---

## 정리

* 현대 컴퓨터 시스템은 네트워크를 통해 다른 시스템과 연결
* 개별 시스템의 관점에서 네트워크 어댑터는 하나의 I/O 장치
* 데이터는 메인 메모리와 네트워크 어댑터 사이를 이동하고, 네트워크를 통해 다른 시스템으로 전달
* 운영체제는 네트워크의 복잡한 하드웨어 세부 사항을 추상화
* 프로그램은 Socket 등의 인터페이스를 사용하여 네트워크 통신 수행
* 네트워크를 통해 여러 시스템을 연결함으로써 웹, 클라우드, 분산 시스템 등의 기반 구성

```text
Application
    ↓
Operating System
    ↓
Network Adapter
    ↓
Network
    ↓
Remote System
```

> **네트워크는 하나의 시스템 관점에서는 또 다른 I/O 장치이며, 이를 통해 프로그램의 데이터 이동 범위가 다른 컴퓨터까지 확장됨.**
